# ADR-0001: 저장소로 localStorage 채택

- Status: Accepted
- Date: 2026-09-09

## Context

미니다이어리는 개인용, 로그인 없음, 주로 단일 기기에서 쓰는 가벼운 앱이다. 데이터는 텍스트뿐이며 하루 최대 40개 항목(4카드 × 10개) × 수년치를 쌓아도 브라우저 저장 한도(~5MB) 대비 극히 일부다. 후보로 `localStorage`, `IndexedDB`, 클라우드(DB) 저장소를 검토했다.

## Decision

**v1은 localStorage를 쓴다.**

- 설정 0: 서버·계정·네트워크 불필요, 오프라인 동작, 비용 없음.
- 데이터 규모와 사용 형태(개인용·단일 기기)에 정확히 맞는 최소 해법.
- `IndexedDB`는 비동기·구조가 복잡해 이 데이터 규모엔 과함 → 채택하지 않음.
- 모든 저장소 접근은 `app/lib/storage.ts` 한 파일로 격리한다 → 나중에 다른 저장 방식으로 교체해도 화면 코드는 그대로 유지.
- 유실 위험을 보완하기 위해 **JSON 내보내기/가져오기**를 MVP에 포함한다.

## Consequences

- 장점: 구현이 단순하고 즉시 오프라인 동작. 인프라 비용 없음.
- 단점: 브라우저 데이터 삭제 시 유실, 기기 간 동기화 안 됨.
- 보완: JSON 내보내기 파일 1개로 백업·이사 가능(설정 메뉴에서 제공).
- 재검토 시점: (1) 폰과 노트북 등 여러 기기에서 같은 다이어리를 봐야 할 때 → 가벼운 클라우드 저장소(예: Supabase) 또는 JSON 클라우드 동기화 검토. (2) 확실한 자동 백업이 필요해질 때.
- 저장소를 바꾸게 되면 `storage.ts`만 교체하면 되므로 화면/훅 레이어는 영향받지 않아야 한다(이 전제가 깨지면 이 ADR을 superseded 처리하고 새 ADR 작성).
