## 1. 배경 & 기획 의도

- 기존 다이어리 앱은 기능이 많고 복잡해서 매일 쓰기 부담스럽다.
- 한 화면에서 오늘의 상태를 바로 확인할 수 있는 **나만의 가벼운 다이어리**가 목표.
- 단순 할 일(To-do) 목록이 아니라 **"해야 할 일"과 "하지 말아야 할 일"을 함께** 관리한다.

## 2. 핵심 원칙

- 한 화면(스크롤 최소)에서 전체 파악.
- 입력은 버튼 하나 → 카테고리 선택 → 저장. 3스텝 이내.
- 이메일/비밀번호로 로그인, 데이터는 계정별로 MongoDB Atlas에 저장 (근거: [[0002-mongodb-atlas-credentials-auth]]). 테마 등 기기별 UI 설정만 여전히 브라우저 `localStorage`.
- 의존성 최소: Tailwind CSS + tailwind-merge + clsx 만.

## 3. 화면 구성 (단일 페이지)

```
┌───────────────────────────────────────────────────────┐
│  미니다이어리                    [📅] [🌙] [⚙️]         │  ← 헤더 1행
│              ‹  2026년 9월 9일 (화)  ›                  │  ← 헤더 2행(센터)
├──────────────────────────┬────────────────────────────┤
│  Longterm                │  Do Now                    │  ← 상단 2 카드
│  (장기 목표)              │  (오늘 집중할 일)            │
│  ☐ ...                   │  ☐ ...                     │
├──────────────────────────┼────────────────────────────┤
│  Don't                   │  Extra                     │  ← 하단 2 카드
│  (하지 말 일)             │  (기타 · 갑자기 생긴 일)      │
│  · ...   3 지킴 · 1 어김  │  ☐ ...                     │
├───────────────────────────────────────────────────────┤
│  하루의 피드백                                 [ 메모 ] │  ← 하단 회고 메모
│  (오늘 하루 회고 한 줄~여러 줄)                          │
└───────────────────────────────────────────────────────┘
```

- **헤더 1행**: 왼쪽에 앱 이름("미니다이어리"), 오른쪽에 `📅` 날짜 선택 아이콘 버튼(→ 날짜 선택 팝업) · 테마 토글 · 설정.
- **헤더 2행**: 가운데 정렬로 이전/다음 날 이동 버튼(`‹` `›`)과 선택된 날짜(기본=오늘). 과거 날짜일 땐 옆에 "지난 기록 · 읽기 전용" 배지.
- 헤더에 전역 "+ 입력" 버튼은 없다 — 각 카드가 자체 "+ 항목 추가" 버튼을 가지고 있어 카테고리를 먼저 고르고 입력하는 전역 버튼은 중복이라 뺐다.
- 4개 카드는 `flex flex-row flex-wrap`, 각 카드 `basis-1/2` 로 2 × 2 배치(모바일도 동일, 12번 참고).
- 하단에 "하루의 피드백" 메모 영역.

## 4. 카테고리 정의 (확정)

| 라벨 | 뜻 | 상태 토글 |
|---|---|---|
| **Longterm** | 계속 염두에 둘 장기 목표·할 일 | 완료 체크 |
| **Do Now** | 오늘·지금 집중해서 할 일 | 완료 체크 |
| **Don't** | 습관처럼 하지만 하지 말아야 할 일 | "오늘 어김" 토글 |
| **Extra** | 기타 · 예정에 없이 갑자기 생긴 일 | 완료 체크 |

- 4개 카드 **모두 날짜별**로 기록된다. (상시 목록 개념 없음)

## 5. 날짜 구조 (확정)

### 기본 동작
- 첫 진입 시 헤더에 **오늘 날짜**가 표시되고, 보드는 **오늘 날짜**의 항목을 보여준다.
- `📅` 날짜 선택 아이콘 버튼 → 날짜 선택 팝업(월 달력). 날짜를 고르면 그 날의 다이어리를 본다.
- 자정을 넘겨 날짜가 바뀌면(재방문·창 포커스 시 재계산) 보드는 새 "오늘"로 이동.

### 과거 / 오늘 / 미래 날짜
| | 과거 날짜 | 오늘 | 미래 날짜 |
|---|---|---|---|
| 항목 추가 | X | O | O |
| 항목 수정 | X | O | O |
| 항목 삭제 | X | O | O |
| 상태 토글(완료 / 어김) | X | O | X (**계획 모드** — 아직 일어나지 않은 날이라 완료 체크는 당일에만) |
| 하루의 피드백(회고) | X | O | X (회고할 하루가 아직 없음) |
| 지난 항목 불러오기(carry-forward) | – | O | O |
| 보기 | O (**읽기 전용**) | O | O |

- **과거 날짜는 완전 읽기 전용.** 지난 기록은 고치지 않고 그대로 남긴다.
- **미래 날짜는 "계획 모드".** 항목을 미리 적어두고 수정·삭제할 수 있지만, 아직 일어나지 않은 일이라 완료 체크(또는 Don't의 어김 토글)는 못 한다. 헤더에 "예정 · 계획 모드" 배지로 구분.
- 날짜 이동(이전/다음 날 버튼, 스와이프, 방향키, 달력)에 더 이상 미래 제한이 없다 — 과거처럼 며칠이든 미리 넘어가서 계획할 수 있다.

### 항목 이어가기 (carry-forward)
- 새 날(오늘 또는 미래)에 `Longterm` / `Don't` 카드가 비어 있으면, 카드 안에 선택지를 보여준다:
  - **[지난 항목 불러오기]** — 그 이전(과거 또는 오늘) 중 가장 최근에 기록된 날의 해당 카테고리 항목을 **팝업으로 보여주고, 그중 가져올 것만 체크해서 고른다**(기본값은 전체 선택, 원하는 것만 해제). 선택한 것만 복제(내용만 복사, 상태는 초기화, 새 id, date=현재 보고 있는 날짜). 카드 여유 개수(room)를 넘겨 선택할 수 없다.
  - **[직접 적기]** — 카드의 `+ 추가`로 새로 작성.
- `Do Now` / `Extra` 는 성격상 매일 새로 시작(불러오기 없음). 다음 버전 후보.

## 6. 완료 / 상태 표시 (확정)

### 해야 할 일: Longterm / Do Now / Extra
- 항목 왼쪽에 **체크박스**.
- 빈 상태 = 미완료. 체크 = 완료 → 텍스트 취소선 + 회색, 카드 안에서 아래로 정렬.

### 하지 말아야 할 일: Don't
- 체크박스 대신 **상태 토글 1개**.
- 기본값 = "지킴"(아무 표시 없음, 깔끔한 상태).
- 탭하면 = **"오늘 어김"** → 빨간 배지 + 텍스트 빨강.
- 어겼을 때만 한 번 누른다 → 조작 최소, 빨간 표시가 없는 날 = 잘 지킨 날(한눈에).
- Don't 카드 헤더 요약: `N 지킴 · M 어김`.

## 7. 인터랙션

- **카드의 + 추가 버튼** → 해당 카테고리가 기본 선택된 채로 모달 오픈. (오늘·미래 날짜에서 활성, 과거는 비활성)
  - 입력값: 내용(text, 1~80자) + 카테고리 선택(Longterm / Do Now / Don't / Extra — 세그먼트 버튼 4개, 필요하면 바꿀 수 있음).
  - 저장 → 해당 카드에 현재 보고 있는 날짜로 항목 추가. Enter 저장, Esc 닫기.
- **항목 상태 토글**: 6번 규칙대로. (오늘만 — 과거·미래는 불가)
- **항목 수정 / 삭제**: 항목에 마우스 올리면(모바일은 항상) 우측에 ✎ / 🗑. 수정은 인라인 편집. (오늘·미래, 과거는 불가)
- **지난 항목 불러오기**: 5번 carry-forward 규칙대로.
- **메모 버튼**: 하단 피드백을 오늘 날짜 기준으로 저장. (오늘만 가능 — 과거·미래는 읽기 전용)
- **📅 날짜 선택 아이콘**: 날짜 선택 팝업(월 달력). 과거 날짜 선택 시 보드 읽기 전용 전환.
- **테마 토글**: `system → light → dark → system` 순환, 최초엔 `system`(OS 설정 따름).

## 8. 항목 개수 제한 (확정)

- **날짜별 · 카테고리별 최대 10개.**
- 10개가 차면 그 카테고리는 입력 폼에서 비활성 + 안내 문구("카드당 최대 10개").
- 카드에는 그중 **최신(생성순) 5개까지만** 보여준다(데스크탑 기준. 모바일은 카드가 더 좁아서 1개까지만). 항목이 1개 이상이면 항상 "더보기" 버튼을 두고, 누르면 팝업으로 전체 목록(체크/수정/삭제 포함)을 볼 수 있다. 팝업 안에서는 폭이 넉넉해 모바일에서도 항목이 한 줄로 표시된다. 카드 자체가 세로로 길어지는 걸 막으면서 "한 화면에서 전체 파악" 원칙(2번)을 지키기 위함.
- 항목 추가 버튼 라벨은 "+ 추가"(카드/팝업 공통)로 짧게 쓴다.

## 9. 테마 (다크 / 라이트)

- 팔레트(초안)
  - light: 배경 `neutral-50` / 카드 `white` / 테두리 `neutral-200` / 글자 `neutral-800`
  - dark: 배경 `neutral-950` / 카드 `neutral-900` / 테두리 `neutral-800` / 글자 `neutral-100`
  - 상태 색: 완료 `neutral-400`(취소선) / Don't 어김 `rose-500`
  - 카테고리 포인트(선택): Longterm `sky` / Do Now `emerald` / Don't `rose` / Extra `amber`
- `system` 모드일 때는 OS 설정(`prefers-color-scheme`)을 자동 반영.

## 10. 반응형 (확정)

- 데스크탑/태블릿/모바일 공통: **2 × 2 카드**(항상 한 줄에 2개). 모바일에서도 세로 1열로 쌓지 않는다.
- 카드가 좁아지는 만큼 한글 텍스트는 음절 단위로 끊기지 않게 단어 단위 줄바꿈(`break-keep`)을 쓴다.
- 헤더도 좁아지면 날짜 아래로 버튼 줄바꿈.

## 11. v1.1 추가 기능 — 날짜 이동 · 달력

### 이전/다음 날 이동
- 헤더 날짜 양옆에 `‹` `›` 버튼. 과거·미래 모두 제한 없이 이동 가능(14번 v1.2 참고).
- 본문 가로 스와이프로도 이동(세로 스크롤과 충돌하지 않게 가로 이동이 더 클 때만 인식).
- ← → 방향키로도 이동(입력 중 / 팝업 열림 시 제외).
- 날짜 전환 시 짧은 페이드 효과(`prefers-reduced-motion` 존중).

### 월 달력
- `📅` 날짜 선택 팝업이 월 달력 격자(6주 × 7일)로 동작.
- 달 이동, 오늘 테두리, 선택일 채움. 미래 날짜도 선택 가능(14번 v1.2 참고).
- 날짜별 점 표시: `기록`(회색) · `어김`(빨강) · `피드백`(주황). 하단 범례.

## 13. 확정 로그

- 카테고리명 `Delete` → `Don't`.
- `Extra` = 기타 · 갑자기 생긴 일.
- 4개 카드 모두 날짜별. 상시 목록 개념 폐기.
- Longterm / Don't 는 새 날에 "지난 항목 불러오기 / 직접 적기" 선택.
- 과거 날짜 = 읽기 전용, "오늘로 불러오기"만 가능. 오늘 = 추가·수정·삭제 가능.
- 저장소 = MongoDB Atlas(계정별, Prisma 경유) + JSON 백업. localStorage는 v1.3부터 테마(UI 설정)만 남는다. 자세한 이유·재검토 조건은 [[0001-storage-strategy]](대체됨) / [[0002-mongodb-atlas-credentials-auth]] 참고.
- 스택 = Next.js 16 + TS + Tailwind v4 + tailwind-merge + clsx + Prisma + MongoDB Atlas + Auth.js. 상세는 [[ARCHITECTURE]] 참고.

## 14. v1.2 추가 기능 — 미래 날짜 계획

- 날짜 이동(헤더 버튼/스와이프/방향키)과 월 달력에서 **미래 날짜 제한을 없앴다.** 며칠이든 미리 넘어가서 계획을 적을 수 있다.
- 미래 날짜는 **"계획 모드"**: 항목 추가·수정·삭제는 오늘과 동일하게 가능하지만, **완료 체크(또는 Don't 어김 토글)는 불가** — 아직 일어나지 않은 하루라 "완료"라는 개념이 성립하지 않기 때문. 헤더에 "예정 · 계획 모드" 배지(하늘색, 과거의 "지난 기록 · 읽기 전용"과 시각적으로 구분)로 표시.
- **하루의 피드백(회고)은 여전히 당일에만** 쓸 수 있다 — 미래 날짜는 회고할 하루가 아직 없으므로 읽기 전용("기록 없음").
- **지난 항목 불러오기(carry-forward)도 미래 날짜에 그대로 적용.** `latestPriorDate`가 "현재 보고 있는 날짜보다 이전"으로 이미 일반화돼 있어서, 미래 날짜에서도 과거/오늘 중 가장 최근 기록을 불러올 수 있다.
- 5번(날짜 구조)의 표와 인터랙션(7번) 문구를 이 기능에 맞춰 갱신했다.

## 15. v1.3 추가 기능 — 계정 · 클라우드 동기화

- **로그인이 앱 사용의 전제 조건이 됐다.** 로그인하지 않으면 `/login`으로 리다이렉트되고, 다이어리 화면(`/`)에 접근할 수 없다.
- **이메일 + 비밀번호로 로그인 · 회원가입.** 공개 `/register` 페이지에서 누구나 가입할 수 있지만, 데이터는 계정별로 완전히 분리되어 다른 사람의 다이어리를 볼 수 없다.
- **로그아웃**은 기존 `⚙️` 설정 메뉴(`SettingsMenu`)에 항목으로 추가했다 — 새 UI 자리를 만들지 않고 기존 드롭다운을 재사용.
- **데이터 저장소가 브라우저 localStorage에서 MongoDB Atlas(계정별)로 바뀌었다.** 여러 기기(집/회사 PC 등)에서 같은 계정으로 로그인하면 같은 다이어리를 볼 수 있다. 테마(다크/라이트/시스템)는 기기별 UI 설정이라 계속 로컬에 남는다.
- **저장 방식은 이전과 동일하게 "전체 로드 / 전체 교체".** 화면에서 체감되는 동작(추가·수정·삭제·토글)은 이전과 똑같고, 내부적으로 어디에 저장되는지만 바뀌었다.
- **기존 localStorage 데이터가 있던 사용자를 위한 마이그레이션 방법**: 이번 업데이트 배포 전 설정 메뉴의 "JSON 내보내기"로 백업 파일을 받아두고, 로그인 후 같은 파일을 "JSON 가져오기"로 불러오면 그대로 계정 데이터로 저장된다. 별도의 자동 이전 절차는 없다(1회성 수동 단계).
- 자세한 기술 결정은 [[0002-mongodb-atlas-credentials-auth]], 구현 상세는 `docs/rfcs/mini-diary-v3-account-cloud-sync.md` 참고.

## 16. v1.4 추가 기능 — 하단 탭 · 통계 · 개인정보 관리

- 메인 다이어리 화면(오늘 하루 보기)은 계속 한 화면 원칙을 지키되, 성격이 다른 기능(통계, 계정 관리)을 **하단 탭 바**(🏠 홈 · 📊 통계 · 👤 계정)로 분리했다. `/login`·`/register`에는 탭 바가 없다.
- **통계 탭**: 이번 달 기준 Longterm/Do Now/Extra 완료율(%), Don't 지킴·어김 일수, 현재 연속 지킴일수(스트릭)를 보여준다. 새 API 없이 이미 클라이언트에 있는 항목 데이터로 계산한다. 스트릭은 "가장 최근에 어긴 날짜 다음날부터 오늘까지"(어긴 적이 없으면 Don't 카테고리 최초 기록일부터)로 계산.
- **계정 탭**: 닉네임 변경, 비밀번호 변경, JSON 내보내기/가져오기, 로그아웃을 한 곳에 모았다. 기존에 헤더 `⚙️` 드롭다운에 있던 JSON 내보내기/가져오기·로그아웃은 이 탭으로 이전했고, 헤더에서는 제거했다.
- 회원탈퇴(계정 삭제)는 이번 범위에서 제외 — 되돌릴 수 없는 기능이라 필요해지면 별도로 설계한다.
- 자세한 구현은 `docs/rfcs/mini-diary-v1.4-bottom-nav-stats-account.md` 참고.
